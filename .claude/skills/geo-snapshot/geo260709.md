## 🔴 함정 EF (신규·치명) — 호스트 파일 동기화

이 세션 최대 시간 낭비 원인. **에이전트 파일 도구(Edit/Write)로 편집한 내용이 사용자 실디스크(git 작업트리)에 안 닿는 경우가 있음.**

- 관찰: 새 파일(Write로 생성)은 실디스크로 동기화됨(Round 133 스캐너 파일·`.planning/*.md` 정상 커밋). 그러나 **기존 추적 파일의 수정(Edit/Write)은 사용자 `git status`에 "nothing to commit"** 으로 안 잡힘. `git diff` 비어있고 `git ls-files -v`는 `H`(정상). Get-Content로 보면 실파일엔 편집 내용이 있는데 git이 변경을 못 봄(stat 캐시/동기화 지연 추정).
- **우회 해법(검증됨):** 수정본을 **새 파일**로 만들고(`_fix/`, `_patch134/` 등 — 새 파일은 동기화됨) → 사용자가 `Copy-Item _fix\X 원본경로\X -Force`로 덮어쓰기 → `git add` → commit → push. 이 경로로 middleware·page·SidebarShell 전부 반영·배포 성공.
- 보조: `git rm --cached <file>` 후 `git add`, 또는 `git update-index --no-skip-worktree --no-assume-unchanged <file>`도 시도했으나 근본 해법은 **새 파일 patch + Copy-Item**.
- 기타: `.git/index.lock` "File exists"(stale) → 사용자 로컬 `Remove-Item ...\.git\index.lock`. push는 항상 사용자 로컬 터미널(가비아·git 모두 사용자 PowerShell).
- 빌드 게이트는 유효: 패치 파일을 /tmp 복사 후 `npx --yes esbuild --loader:.tsx=tsx <f> --outfile=/dev/null` exit 0 확인(마운트 절단 시 정본 재구성).
