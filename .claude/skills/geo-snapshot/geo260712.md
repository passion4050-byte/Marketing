## 🔴🔴🔴 세션 최대 교훈 — esbuild 게이트 ≠ 타입체크
- **CLAUDE.md 빌드게이트의 `npx esbuild ... --outfile=/dev/null`는 구문(syntax)만 검사하고 TS 타입은 전혀 안 본다.** 이번에 해외 도메인-미러 라우트 3개 커밋(7be147a·6c689d8)의 Vercel 빌드가 전부 실패했는데, 원인은 `guides.ts:154` 타입에러(`Argument of type 'unknown[]' is not assignable to 'ParameterOrJSON<never>[]'`). esbuild는 PASS했으나 `next build`(tsc)에서 fail → 구배포(a41d503)가 계속 서빙되어 `/en/blog`·`/en/clinics`만 404, `/en` 홈은 정상이라 "배포 타이밍"으로 오진하기 쉬웠음.
- **원인 코드:** `getOverseasCards`에서 파라미터 배열을 `const params: unknown[] = [lang]`로 선언 → `sql.unsafe(query, params)` 인자 타입 불일치. 형제 함수들은 인라인 리터럴 `[lang, slug]`(→`string[]` 추론)라 통과. **수정 = `const params: string[]`.**
- **재발 방지 규칙(확정):** 빌드-크리티컬 파일(라우트/lib/sitemap)의 타입 변경은 ① 격리 `tsc`(`/tmp`에 타입 스텁 재현 후 `npx -p typescript@5 tsc --noEmit --strict`) 또는 ② push 후 Vercel 빌드 Ready 실측 — 둘 중 하나로 반드시 확인. esbuild PASS를 "안전"으로 믿지 말 것.
- **배포 진단 절차(확립):** 라우트 404인데 소스 정합이면 → GitHub Actions(deploy hook 발화 여부) → **Vercel 대시보드 `medimaps-projects/medimap-blog/deployments`에서 Error/Ready 실측** → 실패 배포 Build Logs "Find in logs: Error:" 로 타입에러 라인 확보. (Vercel MCP는 이 계정 스코프 403이라 브라우저로.)
